# Anatomy Asset Hosting — Production Static HTTPS Layer

Provider-neutral guide for the 18 Meshopt GLBs. No paid CDN, no NestJS proxy, no DB.

## Source of Truth

- Canonical identities: `frontend/packages/anatomy-core/src/assetManifest.ts` — 18 entries (male+female × 9 systems), `file`, `bytes`, `sha256` generated by `scripts/generate-anatomy-manifest.js` from `3d-assets/<bodyModel>/working/optimized/*.glb`.
- URL resolution: `buildAssetUrl(base, bodyModel, file)` / `getManifestAssetUrl(base, entry)` in `assetManifest.ts`. The manifest carries **no host**; any ordinary HTTPS static host can serve it.

## URL Layout

### Production (any static HTTPS host)

The web resolves every entry as:

```
<base>/<bodyModel>/<file>
```

- `<base>` = `VITE_ANATOMY_ASSET_BASE_URL` with trailing slash ensured (`normalizeAssetBase()`).
- `<bodyModel>` = `male` | `female`
- `<file>` = `skin-meshopt.glb`, `musculoskeletal-meshopt.glb`, `nervous-meshopt.glb`, `cardiovascular-meshopt.glb`, `respiratory-meshopt.glb`, `digestive-meshopt.glb`, `urinary-meshopt.glb`, `reproductive-meshopt.glb`, `lymphatic-meshopt.glb` (per `assetManifest.ts`)

Example with `VITE_ANATOMY_ASSET_BASE_URL=https://assets.anatomiax.example/anatomy/`:

```
https://assets.anatomiax.example/anatomy/male/skin-meshopt.glb
https://assets.anatomiax.example/anatomy/male/musculoskeletal-meshopt.glb
https://assets.anatomiax.example/anatomy/male/nervous-meshopt.glb
...
https://assets.anatomiax.example/anatomy/female/skin-meshopt.glb
...
https://assets.anatomiax.example/anatomy/female/lymphatic-meshopt.glb  (18 total)
```

With `VITE_ANATOMY_ASSET_BASE_URL=https://cdn.example/static/anatomy` (no trailing slash) the same 18 URLs are produced — base is normalized.

Do **not** use the flat `female-` prefix in production; that prefix exists only for local dev.

### Local Development (`/models-dev/` — default, no env needed)

When `VITE_ANATOMY_ASSET_BASE_URL` is unset or `/models-dev/`, resolution is flat to preserve the existing `frontend/web/public/models-dev/*.glb` dev subset (13 representative GLBs, gitignored):

```
 /models-dev/skin-meshopt.glb
 /models-dev/musculoskeletal-meshopt.glb
 /models-dev/nervous-meshopt.glb
 /models-dev/female-skin-meshopt.glb
 /models-dev/female-nervous-meshopt.glb
 ... (flat, female- prefix)
```

Reproduce dev copies from optimized sources:

```bash
# from repo root
cp 3d-assets/male/working/optimized/*.glb frontend/web/public/models-dev/
cp 3d-assets/female/working/optimized/*.glb frontend/web/public/models-dev/female-*.glb
# or: for i in female/working/optimized/*.glb; do cp "$i" "frontend/web/public/models-dev/female-$(basename "$i")"; done
```

Fresh clone works without these files; viewer shows loading/error boundaries.

### Dev vs Prod Distinction

| Concern  | Dev (`/models-dev/`)                               | Prod (`https://…/`)                                                               |
| -------- | -------------------------------------------------- | --------------------------------------------------------------------------------- |
| Host     | Vite dev server (`vite` serves `public/`)          | Any static HTTPS host (S3, GCS, R2, Netlify, Vercel static, nginx, Apache, Caddy) |
| Layout   | flat, `female-` prefix                             | `<base>/<bodyModel>/<file>`                                                       |
| Files    | 13 representative (subset)                         | 18 full (male+female ×9)                                                          |
| Tracking | `public/models-dev/*.glb` gitignored               | `3d-assets/**/working/optimized/*.glb` gitignored; manifest is the contract       |
| Env      | omit or `VITE_ANATOMY_ASSET_BASE_URL=/models-dev/` | `VITE_ANATOMY_ASSET_BASE_URL=https://…/`                                          |

No backend proxy: the API never serves GLBs; the web fetches directly from the static host via `useGLTF` (three/meshopt decoder). This keeps the Meshopt pipeline unchanged.

## Required HTTP Host Configuration (provider-neutral)

Configure the static host (or reverse proxy) to emit these for `*.glb`. Examples use generic header syntax; map to your provider's config (S3 metadata, GCS `Cache-Control`, nginx `add_header`, Netlify `_headers`, Vercel `vercel.json` headers, etc.).

### 1. HTTPS

- Serve only over `https://`. Mixed content is blocked by the web.
- HSTS recommended (`Strict-Transport-Security: max-age=31536000; includeSubDomains`).
- No credentials/cookies needed for GLBs.

### 2. Content-Type

```
Content-Type: model/gltf-binary
```

Do **not** use `application/octet-stream` or `application/gltf`. `model/gltf-binary` is the registered type for `.glb` (also accepted: `model/gltf+json` for `.gltf`). Verify with `curl -I`.

### 3. CORS

The web and the asset host are different origins in production, so `fetch` from `useGLTF` requires:

```
Access-Control-Allow-Origin: https://<your-web-origin>
# or for public assets: *
Access-Control-Allow-Methods: GET, HEAD, OPTIONS
Access-Control-Allow-Headers: Range
Access-Control-Expose-Headers: Content-Length, Content-Range, ETag, Accept-Ranges
Vary: Origin
```

Preflight (`OPTIONS`) must return 204/200 with the same `Allow-Origin`. Without CORS the viewer fails with a CORS error, not a GLB decode error.

### 4. Cache-Control

GLB bytes are content-addressed by `manifest.sha256`; ETag + immutable caching is safe.

Recommended:

```
Cache-Control: public, max-age=31536000, immutable
```

If your host cannot emit `immutable`, use `max-age=31536000` plus `ETag`. Do **not** disable caching (`no-store`) — GLBs are 0.6–14 MB and benefit greatly. On asset update (new `sha256`), deploy new bytes under the same `<bodyModel>/<file>` URL with a new `ETag` and optionally a cache-busting query `?v=<shortHash>` (see Versioning); clients will revalidate via `If-None-Match`.

Dev host (`/models-dev/`) uses Vite's default (no immutable needed).

### 5. ETag

```
ETag: "<hex-sha256-or-strong-validator>"
```

- Prefer a strong validator derived from the file (e.g., `"<sha256>"` or provider's S3 ETag which is MD5 for non-multipart). The manifest `sha256` is the canonical validator; the HTTP `ETag` should reflect the same bytes.
- Enables `If-None-Match` 304 revalidation and `check-anatomy-assets` verification.

### 6. Range Requests

Large GLBs benefit from `Accept-Ranges: bytes` + `206 Partial Content` support (three's loader may not require it, but range enables resumable and CDN slicing). Configure:

```
Accept-Ranges: bytes
```

And respond correctly to `Range: bytes=0-...` with `206`, `Content-Range`, `Content-Length`. Most static hosts (S3, GCS, nginx `auto`, Netlify, Vercel) already do this; verify with `curl -H "Range: bytes=0-99" -I`.

### 7. Other

- `Content-Length` must equal `manifest.bytes` (the readiness script checks this).
- No `Content-Encoding: gzip/br` for GLBs (they are already Meshopt compressed; double compression wastes CPU and breaks `Content-Length`).
- Optional `Cross-Origin-Resource-Policy: cross-origin` if you set CORP.

## Versioning / Hash Strategy

Filenames are **preserved** (`skin-meshopt.glb`, etc.). Do not rename/move all 18 assets to hashed filenames blindly — existing references (`anatomySystems.ts` via `buildAssetUrl`) and the manifest would break, and the 3d-assets optimization pipeline would need churn.

Strategy uses the existing `manifest.sha256` without renaming:

- **Immutable cache-safe URL (preferred):** append `?v=<shortHash>` where `<shortHash>` is the first 8 hex chars of `sha256` via `getVersionedAssetUrl(base, entry)` in `assetManifest.ts`.
  - Example: `https://assets.example/anatomy/male/skin-meshopt.glb?v=afe1a889`
  - Keeps filenames stable, busts CDN/browser cache on content change, `Cache-Control: immutable` remains safe because the query changes the cache key.
  - Viewer does not yet append `?v=` — it fetches the canonical `<base>/<bodyModel>/<file>`; add `?v=` only when you need immutable deployment (e.g., CDN with long edge TTL). Both forms serve the same bytes.
- **ETag revalidation (default):** keep canonical URL, rely on `ETag`/`If-None-Match` 304. Simpler, no code change.
- **Hashed filename (only if you must):** if your host requires fingerprinted filenames, map `file` → `skin-meshopt.<shortHash>.glb` at deploy time and update `VITE_ANATOMY_ASSET_BASE_URL` + manifest generation. Not recommended; requires tested migration of `generate-anatomy-manifest.js` and `public/models-dev` layout. Do not do this without a tested script.

`scripts/generate-anatomy-manifest.js` already enforces deterministic `bytes` + `sha256`; the manifest is the single source for versioning. Do not invent a separate version file.

## Integrity Verification

### HTTP-level (primary)

- Compare `Content-Length` vs `manifest.bytes` and `ETag` vs `manifest.sha256` (or provider ETag) via `scripts/check-anatomy-assets.js`. This is provider-neutral and needs no browser work.

### Browser (optional, no deps)

- `frontend/packages/anatomy-core/src/assetIntegrity.ts` provides `sha256Hex(buffer)` and `verifyAssetBuffer(buffer, expectedSha256)` using `crypto.subtle` (Web Crypto, no new dependency).
- Not used by the viewer at runtime — decoding a 14 MB GLB twice (fetch + hash) would add latency. Use it only for diagnostics or a manual “Verify assets” tool:
  ```ts
  import { findManifestEntry } from '@anatomiax/anatomy-core';
  import { verifyAssetUrl } from '@anatomiax/anatomy-core/assetIntegrity';
  const entry = findManifestEntry('female', 'nervous')!;
  const { verified } = await verifyAssetUrl(url, entry);
  ```
- For script/CI verification with Node, use Node's `crypto.createHash('sha256')` (as in `check-anatomy-assets.js` and `assetManifest.test.ts`), not the browser helper.

Do not add `js-sha256`, `spark-md5`, or any new dep — Web Crypto + Node `crypto` are sufficient.

## Production Readiness Check

```bash
# from repo root — checks 18 URLs via HEAD (and GET+hash when --verify)
node scripts/check-anatomy-assets.js --base https://assets.example/anatomy/
node scripts/check-anatomy-assets.js --base https://assets.example/anatomy/ --verify  # also GET+SHA-256
# local dev flat layout — checks public/models-dev/*.glb existence instead of HTTP
node scripts/check-anatomy-assets.js --base /models-dev/
node scripts/check-anatomy-assets.js  # defaults to VITE_ANATOMY_ASSET_BASE_URL or /models-dev/
```

The script is provider-neutral, no paid service, no upload, no proxy. It validates:

- 18 URLs resolve (200, not 404)
- `Content-Type: model/gltf-binary`
- `Content-Length` == `manifest.bytes`
- `ETag` present (and optionally SHA-256 verified with `--verify`)
- `Cache-Control` and `Accept-Ranges` presence (warnings, not failures)
- CORS headers when origin supplied

See `scripts/check-anatomy-assets.js` for flags and exit codes.

## Fresh Clone Instructions

1. `npm ci`
2. For local viewer preview, either:
   - Skip GLBs — `/human` loads and shows error boundaries (still passes `npm run test`), or
   - Populate dev GLBs: `cp 3d-assets/male/working/optimized/*.glb frontend/web/public/models-dev/` and `for f in 3d-assets/female/working/optimized/*.glb; do cp "$f" "frontend/web/public/models-dev/female-$(basename "$f")"; done` (gitignored; never commit).
3. For production deploy:
   - Upload the 18 `3d-assets/<bodyModel>/working/optimized/*.glb` to `https://<host>/<base>/<bodyModel>/` (e.g., via `aws s3 sync`, `gsutil cp`, `rclone`, or static-host UI — no tool is mandated).
   - Configure headers per this guide.
   - Set `VITE_ANATOMY_ASSET_BASE_URL` to the HTTPS base and `npm run build -w @anatomiax/web`.
   - Run `node scripts/check-anatomy-assets.js --base <your-https-base>`.

## What Is Not Done

- No GLBs are uploaded by this step; no CDN vendor is locked in.
- No NestJS route proxies GLBs.
- No anatomy registry/search/3D behavior changed; `anatomySystems.ts` still uses `buildAssetUrl` with the same `available` flags.
- No `female-` prefix is used in production; local `public/models-dev` remains flat for backwards compatibility.
